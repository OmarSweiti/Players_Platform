# ADR-0008 — Arabic and English, equal, from the first screen

**Status:** Accepted · 28 September 2026 · **Requirements:** SR-CORE-007, SR-NFR-I18N-001, UX-008,
TEST-010 · **Owners:** `0.9.2`, `0.9.3`

## Context
The web app is English-only (`lang="en"`, a Latin typeface); the product is Arabic-first for its users.

## Decision
`next-intl` with locale routing (`/ar/…`, `/en/…`); `<html lang dir>` rendered on the server; an
Arabic-capable, licensed typeface; catalogs with identical keys and ICU plurals; logical CSS only,
enforced by lint; bidi isolation for identifiers, emails and mixed-script numbers; the backend returns
codes and the frontend translates them. Both locales ship every screen together.

## Alternatives rejected
Translating after the English UI is built (every screen retrofitted); CSS `direction` flipping of
physical properties.

## Consequences
Every UI microstep carries both catalogs and a Playwright run in each locale.

## Revisit when
A third language is required.
